# 后台管理总览

GoPress 的后台 CMS 完全数据驱动。核心内容类型由引擎注册，主题自定义内容类型由 `theme.toml` 声明；进入后台时会按当前注册表自动生成对应的列表/编辑/创建页面。

后台主要分为 Dashboard、内容与分类管理、系统管理三组。侧边栏由核心内容
类型、当前主题元数据、插件能力和已注册后台路由共同生成，不依赖固定主题。

## 核心特性

- **数据驱动** — 后台界面根据 `ContentType` 注册表动态生成，无需手写 CRUD 页面；侧边栏名称与图标来自 `ContentTypeDef` / `theme.toml`
- **RBAC 权限控制** — 所有后台页面均经过 `checkPermission` 检查（媒体/缓存/重定向/插件管理等）
- **角色体系** — 超级管理员 / 编辑 / 作者 / 投稿者 / 订阅者，超级管理员 `*.*` 通配
- **审计日志** — 记录所有后台操作（用户/动作/资源/IP）
- **Dashboard** — 展示站点内容概览、最近操作和插件通过受保护扩展点贡献的
  统计组件

## 内容管理

- **统一编辑界面** — 所有内容类型共用同一套列表/编辑/创建模板，支持 Meta 字段自动渲染
- **受控编辑状态** — 通用编辑器支持 `published`、`pending`、`draft`、`archived`。服务端只接受白名单状态并忽略伪造值，普通编辑器也不能直接把内容改成 `trash`；`pending` 可用于前台用户提交及其他审核队列
- **显示选项与分页** — 内容列表右上角提供 WordPress 风格「显示选项」面板；表头列选项根据当前内容类型实际列动态生成，包括核心字段、Meta 字段和已挂载 taxonomy。每页项目数会随页面 key 保存，并用于服务端分页
- **基础筛选与标题搜索** — 内容列表支持按标题搜索、按月份筛选和按当前内容类型挂载的 taxonomy 筛选。分页、搜索、语言 Tab、日期和分类筛选会共同作用于同一组服务端查询，因此总数和页码与实际结果一致
- **富文本编辑器** — 集成 Quill 2.0 编辑器，支持图片上传、格式化排版，编辑区右下角可拖拽纵向缩放
- **媒体选择器** — 模态窗口浏览/搜索/上传图片，一键插入
- **内容列表过滤 Tab（可扩展）** — 列表上方 Tab 条由 `admin.HookContentListTabs` filter 动态生成，core 只定义抽象（`ContentListTab` 数据结构 + hook 名），插件按需注入。多语言插件启用时自动出现「全部 / 🇬🇧 English / 🇨🇳 中文」等按语言分组 Tab，带计数徽章；插件停用后 Tab 自动消失，列表回退单语言视图
- **内容列表拖拽排序** — 只要 `ContentType.Supports` 含 `"sort_order"`，列表首列出现拖拽柄（⋮⋮），鼠标拖行后自动 `POST /admin/{slug}/reorder` 重写 `sort_order` 列、就地更新序号 + 右下角 toast 反馈。与语言 Tab 天然解耦：在某语言 Tab 下拖动只影响该语言的内容行，其它语言 `sort_order` 完全独立
- **分类管理** — 分类和标签的增删改查；主题内容类型通过 `theme.toml` 挂载后自动出现在对应编辑界面

## 系统管理

- **主题管理** — 在后台切换主题，实时生效（自动重建路由）。主题包的卡片会显示来源，标出「未签名」「已撤销」的版本，市场有新版本时显示「有新版本」（安全更新为红色）；已撤销的版本不能切换
- **主题市场** — 入口在主题管理页。「浏览市场」每次进入都实时拉取市场目录，可以搜索、安装、升级；市场为主题提供了介绍页时，点卡片的标题、截图或「详情」会在新标签页打开它。目录拉取失败时显示错误和「重试」，不会显示旧列表。「已安装」列出全部已安装的主题包（包括已损坏的），可以查看版本和更新提示、回滚、卸载。「上传主题包」用来安装 `.zip`。详见[主题包](../themes/theme-packages.md#安装和管理)
- **插件管理** — 激活/停用插件（状态持久化，启停自动刷新前台缓存，支持运行时完全热拔插，无需重启服务）
- **菜单管理** — 创建/编辑/删除菜单，分配显示位置（header/footer），拖拽排序菜单项，支持嵌套子菜单。详见 [菜单管理](menus.md)
- **缓存管理** — 查看缓存状态，一键清除
- **重定向管理** — 管理 301/302 规则
- **媒体库** — 上传和管理文件，支持一键重建历史图片的响应式变体
- **邮件设置** — 配置 SMTP 传输、选择 go-mail 或 Go 标准库驱动、发送测试邮件、控制新联系留言通知；SMTP 密钥写入当前站点 `config.toml` 的 `mail.mail_key`，后台不回显真实值
- **用户管理** — 创建用户、分配角色和启用/停用账号。取消“启用账户”后会明确保存 false；该账号已有的后台 Token 与前台 Session 在下一次请求即被拒绝，无需等待过期
- **评论管理** — 按待审核、已批准、垃圾评论和回收站筛选并执行审核操作
- **Agent / MCP 管理** — 激活默认停用的 `gopress-mcp` 后，可在独立插件设置页
  查看连接诊断、配置只读/Safe Write 策略、签发或撤销短期 Token，并按 Tool
  与状态查询调用审计。设置与每个自定义接口分别执行专用 RBAC，不复用“已登录”
  作为授权判断。详见 [GoPress MCP（Agent 接入）](../plugins/gopress-mcp.md)

## 站点设置

后台「系统设置」里的「网站设置」区域是 GoPress 的"WordPress 常规设置"等价物，提供：

- **网站名称** (`site_name`) — 全主题统一来源，控制浏览器 `<title>` 拼接
- **网站简介** (`site_description`) — 全主题统一的 `<meta description>` 默认值
- **网站图标** (`site_icon`) — 全主题统一的 favicon / Apple touch icon 来源，建议上传方形 PNG（至少 48×48，推荐 512×512）
- **站点语言** (`site_language`) — 默认 i18n fallback 语言
- **站点时区** (`site_timezone`) — 后台发布时间输入、内容列表发布时间展示、主题日期 helper 的统一时区来源。文章发布时间会按该时区解析并以 UTC 存储，避免编辑时被服务器时区或浏览器时区反复偏移
- **当前主题** — 显示活跃主题；切换在「主题管理」页
- **演示数据导入状态** — 系统维护，无需手动改

修改后立即生效，整页缓存自动失效。详见 [URL 与 SEO](../architecture/url-seo.md) 和 [主题 SEO 接入规范](../themes/seo-integration.md)。

插件的启用状态只能在「插件管理」页修改，设置页里只读显示；自定义选项也不能覆盖 GoPress 自己管理的设置项。

设置页下方的「开发者选项」是独立的区块，只有拥有 `extension.developer_mode` 权限的角色（默认只有超级管理员）能看到。开发者模式允许安装没有可信市场签名的主题包。打开时要确认风险并输入当前账号的密码，密码连续输错太多次会被锁定 15 分钟；关闭不需要密码。开启期间，后台每个页面顶部都有提示横幅。`config.toml` 里的 `[market] lock_developer_mode` 可以让它始终关闭，见[配置文件](../getting-started/configuration.md#market)。

正在使用的主题版本被市场撤销时，主题仍会继续运行，后台每个页面都会显示提示横幅，直到切换到其他主题或升级。

## 通知

来自 GoPress 和插件的通知显示在后台每个页面的顶栏下方：严重为红色，警告为
琥珀色，提示为蓝色，并带有「安全」「配置」等类别标签。最多展开 3 条，其余
收起为「还有 N 条通知」。

每条通知提供以下一种或两种关闭方式，都只对你自己生效：

- **×**：暂时关闭。到期后（提示文字会写明时间，默认 24 小时）如果仍然适用，
  会再次显示。
- **我已知晓**：不再显示。如果通知内容有实质变化、需要重新阅读，会再次显示。

关闭记录按用户保存在服务器上，换浏览器也有效，两种操作都会写入审计日志。
通知过期或它所说的问题解决后会自动消失。查看通知需要 `notice.read` 权限
（默认只有超级管理员），单条通知可以另设权限；插件可以通过 `admin.notices`
添加通知，见[后台扩展点](extension-points.md#后台通知)。

**GoPress 官方公告。** 更新检查开启时（系统设置 →「官方更新检查与 Beta 使用情况
反馈」），每天的更新检查还可能带来 GoPress 项目的公告，例如针对你正在运行的版本
的安全通告。公告显示在通知中心，拥有 `notice.read` 权限的人可以看到，提供「×」和
「我已知晓」两种关闭方式；过期后，或站点升级到不受影响的版本后，会自动消失。公告
由项目离线签名，站点只接受用 GoPress 内置公钥签名的公告包，所以控制更新服务器的人
也写不出公告；站点也会拒绝比已收到的更旧的公告包。关闭更新检查后不再接收公告。

## 账号安全

后台顶栏的 **账号安全** 是每个后台用户为自己的账号开启两步验证的地方。开启后，
登录时除了密码，还要输入手机验证器 App（例如 Google Authenticator）上的 6 位
验证码。

- **开启**：输入当前密码，用 App 扫描二维码（或手动输入密钥），再输入 App 显示的
  验证码。随后会显示 10 个恢复码，只显示这一次，可以下载或复制。开启后当前会话
  保持登录，这个账号在其他设备上的登录全部失效。
- **登录**：输入密码后，再输入 App 上的验证码，或改用恢复码。每个恢复码只能用
  一次；少于 3 个时通知中心会提醒重新生成。15 分钟内输错 5 次验证码，会锁定
  15 分钟。
- **敏感操作**：已开启两步验证的账号，在打开开发者模式、把账号设为超级管理员、
  在用户页设置密码、重置他人的两步验证、修改「必须开启的角色」、重新生成恢复码
  时，都要输入新的验证码。每个验证码只能用一次，30 秒内连续做两个这样的操作需要
  两个验证码。恢复码只能用于登录和关闭两步验证。
- **必须开启的角色**：有权修改设置的用户可以在 **必须开启的角色** 里选择角色。
  这些角色的账号设置完成前只能打开账号安全页，也不能关闭两步验证。默认不要求任何
  角色。
- **关闭**：需要密码，以及验证码或恢复码。
- **手机和恢复码都丢了**：请另一位超级管理员在用户页打开这个账号，点
  **重置两步验证**；这个账号会在所有设备上退出登录，下次登录后重新设置。没有其他
  超级管理员时，在服务器上运行 `-reset-2fa`，见
  [安装](../getting-started/installation.md#重置两步验证)。

两步验证保护的是后台登录。`config.toml` 里的 API 密钥和 Agent 凭证不经过登录，
不受它影响。开启、关闭、重置、使用恢复码和输错验证码都会写入审计日志；邮件已配置
时，两步验证被关闭或重置、恢复码被使用、重新生成恢复码时，会给账号邮箱发提醒。

## 邮件设置

后台「邮件设置」是独立系统页，不混入普通 options 表单。SMTP 传输配置保存在站点级 `config.toml` 的 `[mail]` 段，通知开关和收件人偏好保存在 options。默认发信驱动是 `go-mail`，也保留 `stdlib` Go 标准库分支。

- **SMTP 总开关** — 关闭时不投递邮件，但通知规则保留
- **SMTP 密钥** — `mail.mail_key` 只写入配置文件；后台只显示“已设置”占位，留空表示保留，勾选清除才会删除
- **Gmail 配置** — 使用 `smtp.gmail.com`、`587`、`STARTTLS`，SMTP 用户名和发件人邮箱都填 Gmail 地址，SMTP 密钥填 Google App Password
- **测试邮件** — 使用当前已保存配置发送，便于上线前确认主机、端口、加密方式和发件人是否正确
- **联系留言通知** — 当前默认规则是 `contact_message` 创建后异步通知管理员邮箱；失败只写日志，不影响留言保存

## 扩展性

后台不是封闭面板——core 提供了一系列扩展点（filter / action hook）让插件向后台注入功能：

- 内容列表过滤 Tab
- 内容编辑页永久链接前缀
- 内容编辑页自定义 meta box
- 内容保存后的副作用 hook
- 插件设置页（自带模板、自带数据、自带保存回调）
- 后台通知（每个页面顶部的横幅）
- 需要两步验证码的敏感操作

详见 [后台扩展点](extension-points.md)。
